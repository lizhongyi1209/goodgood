# ADR 0088 — 可寻址的登录与注册入口

- 状态：Accepted；日期：2026-09-15；任务：GG-096；部分替代 ADR 0087 的“单一表单且无登录/注册切换”界面决定。

## 背景

GG-095 将本地正常测试入口切换为真实的邮箱验证码流程，但认证界面仍是覆盖工作区的阻断层：未登录访问 `/` 时地址不变，注册入口仅在后端返回 `INVITATION_REQUIRED` 后出现。该行为不适合按上线规格检查，也无法直接刷新、分享或验证登录与注册两个入口。

## 决定

- 新增正式、可直接访问的 `/login` 与 `/register` 页面；不接受拼写错误的 `/logoin` 作为产品路由。
- 邮箱验证码模式固定显示“登录 / 注册”子导航。登录页不显示邀请码；注册页直接显示六位邀请码字段。
- 所有需要认证的工作区页面在确认未登录后跳转到 `/login?returnTo=...`。旧 pending 账户的“使用邀请码开通”进入 `/register`。
- `returnTo` 只允许站内绝对路径，拒绝协议相对地址、反斜杠、控制字符、认证页自循环和外部地址；无效值回退 `/create`。邮箱、验证码、邀请码和挑战标识不得进入 URL。
- 邮箱验证码提交若确认当前邮箱是新用户，界面自动切换到注册页并保留当前邮箱、挑战和验证码；邀请码仍由后端最终校验。
- 已登录访问认证页面时返回安全的业务目标。验证成功以后端返回的安全 `returnTo` 为准。
- 现有 `email_code` / `hosted` 后端模式边界保持；不新增密码、手机号、社交登录，不改变邀请码归属、验证码冷却、限流、账户状态或生产部署配置。

## 影响

- 认证成为独立的产品路由而非工作区内部状态，浏览器刷新、返回和直接访问具有明确语义。
- ADR 0087 的账户唯一邀请码、邮箱验证码和服务端校验决定继续有效；仅其“无登录/注册切换、邀请码统一展示”的界面决定被本 ADR 取代。
- 本地实现和验证不表示生产已部署；发布状态仍以 `docs/CURRENT_STATE.md` 为准。
