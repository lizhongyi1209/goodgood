# ADR 0089 — 邀请码改为可选注册

- 状态：Accepted；日期：2026-09-15；任务：GG-097；部分替代 ADR 0086 与 ADR 0087 中「邮箱验证码加邀请码共同注册」的界面与准入决定。

## 背景

ADR 0086/0087 要求新账户必须同时提供邮箱验证码**和**一位 active 用户的六位邀请码。这在本地与早期 alpha 阶段可用，但在 2026-09-15 的 GG-097 生产发布准备中暴露为硬阻断：

- 生产用户数已为 0（GG-091 清理，含站长），因此不存在任何 active 用户；
- `server/auth/email-repository.mjs` 只接受属于 `status='active'` 用户的邀请码；
- 而 `server/admin/bootstrap-site-owner.mjs` 又要求目标邮箱已经登录过一次才存在 `users` 行。

三者互相依赖，形成「无邀请码 → 无法注册 → 无 active 用户 → 无邀请码」的死锁：email_otp 模式下无法创建第一个账户，也无法引导站长。用户明确要求解除强制邀请码。

## 决定

- 邀请码改为**可选**：未提供邀请码时，新邮箱验证成功即可创建账户。
- 邀请码一旦提供，仍然**必须有效**：六位格式且属于 active 用户；不匹配返回 `INVITATION_INVALID`，不创建账户，并计入该挑战的失败次数。
- **待开通账户仍受约束**：已存在且 `status='pending'` 的账户，在未提供邀请码时仍返回 `INVITATION_REQUIRED`，不得凭邮箱验证码自行激活。
- 注册页保留邀请码输入框，标注为「邀请码（选填）」；未填写不阻止提交，只在填写了非六位内容时禁用提交。
- 提供有效邀请码时继续写入 `account_invitation_uses`，保留邀请人追溯能力；未提供时不写入。
- 邀请码的随机分配、唯一性、展示位置（余额下方纯文本）、`GOODGOOD_EMAIL_REGISTRATION_ENABLED` 开关、验证码冷却与限流均不变。

## 影响

- email_otp 模式可以自行完成首个账户创建，GG-097 的启动死锁解除。
- 准入控制重心从「邀请码」移到 `pending` 与站长审批；新注册账户依既有实现直接为 active，因此**开放注册即等于可创作**，站长如需收口须依赖注册开关。
- ADR 0086 / 0087 中与强制邀请码相关的界面与准入描述被本 ADR 取代；其邀请码归属、六位格式、冷却与限流决定继续有效。
- 本地实现与验证不代表已部署；发布状态仍以 `docs/CURRENT_STATE.md` 为准。
