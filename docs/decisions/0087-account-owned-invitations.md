# ADR 0087 — 账户唯一邀请码与统一验证表单

- 状态：Accepted；日期：2026-09-14；任务：GG-091；替代ADR0086的站长发放单次码与登录/注册切换。
- 后续：ADR0088取代本记录的“单一表单且无登录/注册切换”界面决定；账户唯一邀请码、邮箱验证与服务端校验规则继续有效。
- 用户明确：每个账户仅一个随机6位数字邀请码，固定且可无限次邀请；显示在本人积分余额下方，按用户补充要求仅作文本展示，不提供整行点击或复制按钮。邀请码是公开分享标识，账户仍须邮箱验证码认证，不授予角色、不兑换奖励。
- 持久化：账户创建事务自动分配唯一6位字符串（允许前导0，碰撞重试）；既有账户按新增迁移补齐。邀请关系单独记录，正确验证码后仅活动邀请者的码有效；不消耗/更换邀请者码。邀请码不得用作认证凭据。
- 单一表单：邮箱、六位邮件验证码、六位邀请码、确认；无登录/注册切换或修改邮箱按钮。老用户确认邮箱即可登录，邀请码字段统一展示且标注新用户填写，后台新用户/旧pending必须邀请码；已开通老用户不因邀请者停用而不能登录。
- 邮箱始终可编辑（验证提交期间除外）；更改地址后清除当前挑战/邮件码并重新发信，旧邮箱验证码不能验证新地址；保留请求开始时邮箱快照，避免异步发信响应绑定到后改邮箱。现有浏览器绑定、失败上限、冷却、限流保持。
- 停止后台额外生成邀请码，原0042表仅保存历史，旧长码不再用于注册。邀请人暂停时禁止新的邀请注册；已有邀请关系保留。
- 线上清理：用户明确“线上的测试用户，删除所有”；只清理核对出的既有测试用户及其测试数据/对象/队列，含站长测试账户，不部署本地功能。先新备份、核对无活动任务/冻结积分、隔离演练清理与保留全局配置，原服务器上维护窗口执行；不运行旧转换/全库重置脚本，不复制生产数据回本地。
