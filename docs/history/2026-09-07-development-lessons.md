# 历史开发提炼（截至 2026-09-07）

## 保留的产品决定

- 工作台以图片与反复创作为中心，设计以根 AGENTS/DESIGN_SYSTEM 为准，不能
  因换 agent 重做成营销页、另一套品牌或通用聊天页。
- 浏览器只访问 GoodGood 后端，后端隔离身份、模型路由、积分和私有存储。
- 先香港现有单机、现有 R2；本机开发，CI 不可变镜像晋级；扩容依实际观测。
- 公开注册 + 待审核 + 100 欢迎积分 + 站长人工补分；不是无门槛匿名生图。
- 无新增固定生成上限；保留内存/磁盘保护，不为了“安全”擅加串行排队限制。
- 国内支付宝、完整删除/举报体系、复杂监控后置；当前只承诺 ADR 0024 alpha。

## 关键进展（不必重跑）

1. M0–M7：界面契约、持久任务、身份/权限、模型路由、积分和香港链路逐步验证。
2. M8：站长账户管理、现有主机转生产、生产私有数据/密钥/备份与维护边界落地。
3. 原 C6 扩张到完整删除/举报/恢复能力，但未部署；用户选择更窄 alpha 门禁。
4. C6-3 核心用户/恢复/基础观测检查完成，C7 经明确授权开放；不要重新做迁移清空。
5. ADR 0025 的 14 宽高比 × 三档分辨率发布到 `94cecb0`，线上数据库保持 0012。
6. GG-001 将 deferred C6 保全到独立分支/worktree，建立可跨窗口的短入口。

## 反复出现的问题，转成规则

- 旧入口说“只是原型” → 部署事实只集中在 CURRENT_STATE，其他入口链接过去。
- 超长计划有多个“下一步” → 单一短检查点，具体进展写任务卡，历史只按需读。
- 未完成的 C6 混进新发布 → 独立分支/worktree，发布核对 migration 与 diff。
- 域名/SSH 别名含 staging → 看实际绑定和 CURRENT_STATE，不能凭名字判断环境。
- 在截图里猜控制台设置 → 先看代码和官方/实际控制台证据，最小权限，秘密不进聊天。
- 本地、API 与浏览器证据混用 → 每层分别记录，未验证明确保留，不伪造“全部通过”。
- 一次请求变成庞大的配套工程 → 新任务按实际测试阶段需求定范围，搁置项不自动复活。
- 自动执行时间长后授权模糊 → 记录本任务范围，批准范围内连续做，超出范围才再问。
- 小需求先扩成全面加固 → 先交付行为完整的最小修改；仅在验收必需或发现可复现缺陷时
  扩展，并记录原因。迭代跑定向测试，代码稳定后完整门禁只跑一次。
- opt-in 积分测试误连真实本地栈 → fixture 写入必须使用显式临时数据库/队列，且确认
  没有真实 O1Key Worker；真实 provider 调用一律视为可能计费并要求站长明确发起。
