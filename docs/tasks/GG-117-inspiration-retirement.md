# GG-117 — 灵感板块整体下线并删除灵感数据表

- Status: 待做；破坏性任务，需站长明确确认丢弃现有案例数据后才执行。
- Baseline: 待定（建议从 GG-116 完成后的检查点开始）。
- 来源: 2026-09-25 站长对 GG-116 的追加指示「灵感版功能可以先删掉，后面再重构」，
  经追问确认为「整体下线，并删除数据表」。

## 为什么单独开卡

GG-116 只做资产库样式与生成历史卡片操作。灵感下线涉及已上线能力的移除与不可逆的
数据删除，范围、风险和授权都不同，不并入触发它的样式需求。

## Scope

代码与路由（`app/inspiration/` 三个页面、`app/api/inspiration/` 路由、
`features/inspiration/` 组件、`server/inspiration/` 模块）全部移除，并处理
导航入口、`app/page.tsx` 中的调用点与相关测试。

数据层删除以下表/数据（执行前必须单独授权）：

- `inspiration_cases` 及其索引；
- 相关的浏览/使用统计记录；
- 灵感专用的参考图关联（`before_reference_id` 指向的素材是否随之清理需单独判断，
  不得误删用户仍然可用的私有素材）。

## 必须先确认的事项

1. 现有 `inspiration_cases` 数据可以丢弃（不可恢复）。生产库现有案例数量需先统计
   并报告。
2. 删除哪些表、保留哪些表：至少 `inspiration_cases` 是站长点名要删的；其余统计表
   由站长确认。
3. 前端入口下线方式：直接移除导航项，还是保留入口并提示功能已下线。
4. ADR 0073—0079 的决策记录处理方式：标记为 Superseded/Retired，不删除历史记录。

## 与 GG-116 的关系

GG-116 的删除接口目前依赖 `inspiration_cases` 的存在来返回 409。本任务删除该表后，
需要在同一变更里移除 `deleteGeneratedAsset` 中的这段检查及其测试，否则会因表不存在
而报错。这是两个任务之间唯一的耦合点，实施时不要遗漏。

## 执行前检查

- 该表被 `assets(id)` 外键引用，删除顺序与依赖必须先列出完整清单。
- 生产数据删除需要单独的恢复方案与授权，本地实现不等于生产执行。
- 迁移必须是单向且可审计的；不得与其它功能发布混在同一次变更里。

## 下一步

等站长在 GG-116 验收后，先统计本地与生产 `inspiration_cases` 行数并回报，确认可丢弃、
确认要删的表清单，再开工；生产删除另行授权。
