## 范围与验收

- 要做：保留 `/credits`；宽屏入口采用与 `帮助` 相同的普通导航行并放在其下方，不显示“点击查看”；移动端余额入口保持不变。
- 要做：可用余额替换用户名下方原“已登录”文案，以 Palace Red 单枚 `CircleDot` 积分图标加数值展示，不显示“余额/积分”文字或胶囊；无障碍名称保留完整含义，读取中和不可用状态保持同一位置。
- 要做：页首显示今日、本周、本月已结算消耗积分。本周从周一开始；当前中文产品以 `Asia/Shanghai` 为业务日历。处理中预留和已释放金额不计入消耗。
- 要做：服务端将账本投影为用户可理解的业务记录。一次生成只显示一条：预留中为处理中，结算为已消费，释放为未扣除；退款和积分获得独立显示。
- 要做：记录只显示 `图片生成 / 视频生成 / 其他变动`、批次编号（如有）、时间、状态和积分变化。图片使用资产库已展示的同一任务/批次编号；不重复模型、分辨率、张数、提示词或结果入口。
- 不做：人民币金额换算、充值、支付、钱包、导出、日期搜索、历史价格推测或计费启用前生成记录回填。没有确认的积分/人民币换算规则，因此“消耗多少钱”本次按积分数表达。
- 验收点：仅当前 owner 可读；不暴露账户、账本、支付或 provider 内部标识；分页倒序无重复；成功生成不因 reserve/settle 显示成双倍扣费；加载、空、失败、重试和窄屏完整。
- 验收点：进入和离开记录页不清空草稿、项目或运行中的生成；浏览器前进/后退与直接刷新保持 `/credits` 语义。
- 决策影响：本轮替换 GG-025 任务内尚未发布的展示方案，不改变已确认的产品/架构决策，无需 ADR。功能仍是现有积分账本的只读用户投影，客户支付和钱包 UI 继续缺席。
- 授权边界：本地实现与验证；未授权合并、推送、真实 provider 请求或生产发布。
