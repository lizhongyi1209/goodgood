# GG-013 — 稳定生成网格与本地下载

- 状态：本地已验证；3010 Web 已就绪，未发布
- 用户需求：多图生成开始时即采用最终排列，完成后原位替换；创作卡片显示实际像素尺寸，移除创作卡片和图片详情的收藏按钮，并直接保存图片到本地而非打开新标签页
- 最后更新：2026-09-08
- 分支：`feature/GG-013-stable-generation-grid-download`
- 依赖基线：本地组合候选 `9d2e679`，包含 GG-004–GG-012；本任务直接修正该候选的并行生成展示
- 决策：[ADR 0034](../decisions/0034-stable-generation-grid-and-download.md)

## 范围与验收

- 生成中占位卡和已完成图片共用同一个创作网格；每次提交按冻结的数量和比例立即占据最终槽位。
- 成功图片使用同一稳定槽位键原位替换，不因完成顺序、临时任务 ID 或并行任务状态而重排。
- 最新提交仍在最前；失败继续使用现有内联恢复条，不暴露半成品。
- 创作图片左下角只显示该资产解码得到的 `宽 × 高`；缺少旧资产尺寸时回退到模型、比例和分辨率对应的产品尺寸。
- 移除创作图片和图片详情右上角的重复收藏按钮；资产库既有选择能力不在本次范围内。
- 创作图片的下载按钮在悬停、键盘聚焦和按下时提供清晰但克制的交互反馈。
- 下载先完整读取并校验图片，再通过浏览器下载管理器保存 Blob；不得导航到图片标签页，也不得在读取成功前创建磁盘目标文件。
- 默认文件名使用 `GoodGood_YYYYMMDD_HHmmss_序号.格式`，时间取批次生成时间，序号取批次内图片顺序，不再暴露冗长的内部 UUID。
- 所有生成结果视图忠实显示原始色彩，不再按第 2/3/4 张规律性应用饱和度、对比度、色相或亮度滤镜。
- 读取或创建下载失败显示可重试提示；浏览器接管下载后显示“图片下载已开始”。
- 本地对象存储允许受控来源对签名对象执行 `GET/HEAD`，下载写盘前拒绝 0 字节响应。
- Blob 对象 URL 延迟释放，避免浏览器接管下载前资源即被回收。
- 覆盖稳定槽位、完成去重、尺寸文本、按钮移除和下载实现的自动化测试。
- 不包含真实付费生成、生产部署或资产/数据库结构变更。

## 实现与证据

- 已实现统一创作流：活动任务按运行键和输出序号创建稳定槽位，成功输出沿用同一键原位替换；当前会话保留成功运行，持久批次在统一流中按 job ID 去重。
- 已将创作卡片悬浮信息改为解码像素尺寸；缺失尺寸时使用模型能力表回退，并移除创作卡片及图片详情的重复收藏按钮。
- 已为创作卡片下载按钮补充宫墙红悬停/聚焦反馈、浅层阴影和按下反馈；禁用下载态不触发悬停效果。
- 已修复本地 RustFS 仅允许 `PUT` 导致签名图片可显示但浏览器跨域读取失败的问题：受控来源现允许 `GET/HEAD/PUT`；保存逻辑在创建 writable 前拒绝空 Blob。
- 用户在首轮 CORS 修复后真实复核仍得到 0 字节文件；第二层修复不再直接写 Blob，而是以 `keepExistingData: false` 创建 writable、写入 `Uint8Array`、关闭后通过 `getFile()` 校验实际大小，不一致即显示失败。
- 用户再次真实复核时，原生保存路径显示失败并留下 0 字节文件，证明保存选择器会先创建目标文件、后续失败仍留下空壳；因此 ADR 0034 已修订，不再直接使用 File System Access API 写盘。
- 当前下载路径会先完整读取并拒绝空响应，再将非空 Blob 交给浏览器下载管理器；对象 URL 延迟 60 秒释放，避免触发下载后立即回收。创作卡片和详情页共用该行为，且不会打开图片标签页。
- 默认文件名已缩短为生成时间加批次内序号，例如 `GoodGood_20260908_143025_01.jpg`。
- 已移除创作流、旧结果卡、资产批次、资产画廊、详情大图和详情缩略图上的序号调色规则；服务端原始字节链路不变。
- 最新下载定向测试 4/4 通过，连同相关 UI 回归共 18/18；最终 `npm run check:local` 共 226 项（220 通过、6 项 opt-in 跳过、0 失败），构建、Lint 和类型检查通过。
- 3010 Web 容器已用当前源码再次重建且 readiness 全部为 `ok`；浏览器刷新后复核现有创作网格、具体尺寸和下载按钮均正常。构建产物确认不再包含 `showSaveFilePicker`，包含新的“图片下载已开始”反馈和空响应保护。本地签名图片此前实测返回 HTTP 200、`image/jpeg`、534742 字节和精确 3010 来源 CORS，允许 `GET/HEAD/PUT`。当前本地账户积分为 0，未调用真实付费生成；用户报告的 0 字节文件未擅自删除。
- 发布：未发布，生产环境未变。

## 恢复工作

- 下一步：由站长在已刷新的 3010 页面再次点击现有图片下载，确认浏览器保存出非零且可打开的图片；随后再使用有可用测试积分的账户复核一次 2/4 张生成中的原位替换，再决定是否进入发布候选。
- 风险：浏览器是否每次显示“另存为”取决于其下载偏好；页面不再直接操作目标文件，因此无法观察用户在浏览器下载流程内取消保存。
