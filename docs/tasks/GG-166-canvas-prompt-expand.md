# GG-166 — 画布提示词溢出时展开查看

- 状态：GG-116 本地未提交界面已修改，待站长手动验收；未部署。
- 请求：当 `/canvas` chat 的提示词输入超过默认可见高度而出现内部滚动条时，在右侧显示小型展开图标；点击后扩展输入区以查看更多文字，再点击可收起。视觉参考站长 2026-09-28 提供的展开前后截图；后续反馈要求光标和滚动条末端远离底部按钮，移除滚动条上下原生箭头，让首行、滚动条起点和展开图标处于同一水平位置、末行与滚动条终点对齐，并只在鼠标悬停提示词区域时显示滚动条，离开后淡出。
- 决策：默认输入仍自动增长到 188px 再滚动；可选展开状态补充了原先固定最大高度的规则。见 [ADR 0108](../decisions/0108-standalone-canvas-image-generation.md) 的 GG-166 补充。

## 范围与验收

- 输入未溢出时不显示控件。溢出时，滚动条右侧出现斜箭头图标；展开后按钮为浅灰圆底的收起图标，输入区按文字内容向上增长，最长受视口高度限制，底部设置、模型、生成控件仍贴在输入区下方。
- 提示词文本、光标、Ctrl/Cmd+Enter 提交、参考图托盘和生成参数不被重置。展开与收起可由键盘操作，按钮有可访问名称、展开状态和可见焦点；缩窄窗口时重新计算是否溢出。
- 控件始终预留紧凑宽度，出现时不使文字反复换行；不观察 React Flow 尺寸或改变画布缩放。
- 本任务实现时输入区底部与工具栏间保留 18px 空隙（窄屏 14px）；该外间距已由 [GG-174](GG-174-canvas-composer-spacing.md) 收紧为 2px，文字下方内边距保留。站长截图确认仅隐藏 `::-webkit-scrollbar-button` 未去掉 Windows 原生箭头，现将提示词滚动条的轨道和圆角滑块一并自定义，使上下箭头不再绘制；滚动能力不变。
- 滚动轨道上、下内缩与文字输入框对应内边距一致：桌面为 10px / 18px，窄屏为 8px / 14px；展开图标按首行文字行高居中。滚动条端点随输入框高度变化，不靠固定屏幕坐标定位。
- 浏览器原生滚动滑块保留滚动与拖动能力但绘制为透明；同位置的轻量可见滑块依照输入框的实际滚动量和可视比例定位，只在内容溢出且鼠标停留于提示词区时显示，离开时约 240ms 淡出。无 hover 的触屏设备持续显示可滚动滑块；减少动态效果偏好下立即切换，短内容不展示。
