## 需求与范围

生成任务进行中时，飞鸿发送按钮仍可点击。每次点击冻结当时的提示词、参考图、
模型、画面比例和分辨率，提交一个独立任务；产品侧不设置并发任务数量上限。

- 一个点击仍生成一张图，每个已接受任务仍按现有规则独立预留 10 积分。
- 多个活动任务同时保留各自的比例骨架、状态、错误、重试和设置恢复入口。
- 较晚提交不得覆盖较早任务，较早完成也不得移到较新提交之前。
- 有任一活动任务时，继续阻止新建创作或切换项目等破坏当前上下文的动作。
- 后端已有并行 Worker 和无固定任务数上限，本任务不改数据库或计费模型。

## 验收

- 活动任务期间发送按钮保持可操作，并用可访问名称表达“继续生成图片”。
- 连续快速提交产生不同运行标识；`pending_*` 更新为服务端任务 ID 时不遗留骨架。
- 任意数量的活动运行不会被客户端截断；成功、失败和重试互不覆盖。
- 项目保存包含全部已持久化任务 ID，临时 pending ID 不进入项目。
- `npm run check:local` 通过；合并到本地联调分支后在 3010 环境供站长实测。
- 不由 agent 触发真实付费生成；不发布生产。
