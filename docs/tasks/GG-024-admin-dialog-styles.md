# GG-024 — 站长账户弹框样式修复

- 状态：待验收
- 来源：站长在本地 `/admin/users` 逐项操作时发现确认弹框透明、控件层级与品牌样式异常
- 最后更新：2026-09-09
- 分支：`fix/GG-024-admin-dialog-styles`
- 基线：`42fc8d81d7f50ea6139671a2c239a0ee2d4455ea`

## 范围与验收

- 检查通过、暂停、恢复和赠送积分四类账户操作弹框；它们继续共用一套可访问的对话框结构。
- 弹框使用不透明白色表面、克制遮罩、明确边界与浅阴影，底层账户表格不得透进内容区。
- 标题、目标账户、原因输入、积分预设/自定义输入、错误区和操作按钮保持清晰层级；确认动作使用宫墙红，取消动作保持中性。
- 桌面与窄屏都保持在视口内，键盘焦点、关闭行为、禁用状态和原有管理流程不变。
- 增加样式契约测试，运行定向测试、`npm run check:local`，并在隔离本地栈逐项打开四类弹框做浏览器验收。
- 不通过页面确认任何账户操作；浏览器验收只在隔离 mock 栈创建站长和 `.invalid` 测试账户，不修改生产数据库、权限或积分，不发起真实 provider 请求。
- 这是现有视觉实现修复，不改变产品决策，无需新 ADR。

## 实现与证据

- 根因是 GoodGood 品牌变量没有映射到 Shadcn/Tailwind 的 `background`、`primary`、`input`、`ring` 等语义色，导致共用 `Dialog` 的表面和控件回退为透明/当前文本色。
- `app/globals.css` 补齐语义色映射，并为账户操作弹框增加不透明白色表面、克制遮罩与模糊、浅阴影、宫墙红主操作、输入焦点、禁用/错误状态及窄屏布局。
- `components/ui/dialog.tsx` 支持为普通对话框单独传入遮罩类；`features/admin/account-management-page.tsx` 让通过、暂停、恢复和赠送积分继续共用同一套专用结构，积分弹框补充当前可用积分上下文。
- `tests/m8-account-admission.test.mjs` 增加四种操作共用不透明 GoodGood 弹框表面的契约测试；定向测试 12/12 通过。
- `npm run check:local` 通过：lint、类型检查和构建成功；253 项测试中 247 通过、6 个 opt-in 跳过、0 失败。
- 隔离 Compose 项目 `goodgood-gg024` 使用 mock provider，Web 位于 `http://127.0.0.1:3020`。以本地站长登录后逐项打开通过、暂停、恢复和积分弹框，桌面及 390×844 窄屏均通过视觉验收；没有点击任何确认动作。
- 隔离数据库仅写入 `m3-local@goodgood.invalid` 站长，以及 pending/suspended 两个 `gg024-*.invalid` 测试账户；现有 3010 本地栈和生产均未改动。
